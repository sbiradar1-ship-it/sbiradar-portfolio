SAP · Principal PM

Legacy keyword search wasn't surfacing the right procurement content across Marketplace, Sourcing, Catalog, and Supplier Management. Led the architecture and launch of a semantic search platform built on NER, vector embeddings, and ML re-ranking.

Incoming queries are parsed with NER-based intent modeling to separate brand, product type, and spec constraints from free text. Retrieval then fans out in parallel across two arms, a lexical BM25 pass and a vector KNN pass over semantic embeddings, and both result sets are merged into a single candidate pool before a Sentence-BERT cross-encoder re-ranks them for relevance, all served in under 500ms at scale. RAGAS-based evaluation (faithfulness, context precision/recall) validated every iteration before rollout. Net effect: an 82% NDCG relevance lift and latency cut from 2s to 500ms, at 50M+ queries/day.

A catalog quality scoring system (rule-based checks plus an XGBoost model) flags low-quality items; catalog admins then use Perplexity AI to generate improved titles, descriptions, specs, and image suggestions, which are surfaced back to catalog providers. Speakly

Turns a whole book into natural narration in a voice you choose, with nothing to install. A FastAPI web tier and a queue-backed worker split the work so an hour-long synthesis never blocks the request path, and rendering runs on a GPU service on a separate machine reached over a Cloudflare tunnel; long documents are chunked for multilingual synthesis, and personal API keys let other applications narrate through a user's own account.

Presently

It finds the moment each slide is announced by transcribing the audio with Whisper on the GPU and aligning the transcript word-by-word against the script — matching titles as well as numbers, so a slide still lands correctly when the recogniser mishears its number — then renders with LibreOffice and FFmpeg using NVENC; every job is a database row, so a long narration survives a restart and resumes where it stopped.

Testly

All six share one operational pattern: a public Ubuntu front door terminating a Cloudflare tunnel with Cloudflare Access authenticating every visitor at the edge, proxying to backends where the GPU and all state live on a private host — so inference data never leaves the network, and each service is reachable only through the edge. Service-to-service calls between products are authenticated with scoped Access service tokens.

AI Document Search — DriveLens

React · FastAPI · Celery/Redis · Postgres · Solr 9 (HNSW) · MinIO · Tika · multilingual-e5-large · BGE Reranker · Helm/K8s

Connect a Google Drive (or any storage drive) and search every document in it by meaning, not just keywords — a multi-tenant hybrid search platform with an ACL-aware index that stays true as Drive changes.

What it does

A Google Drive (or any storage drive) semantic document search platform. You sign in with Google, pick folders (or the whole Drive), and a seven-stage pipeline crawls, extracts, chunks, embeds, and indexes every document into Apache Solr. Search then runs two arms in parallel — a BM25/edismax lexical arm and an HNSW dense-vector arm over 1024-dim multilingual E5 embeddings — fused with Reciprocal Rank Fusion, so an English query surfaces the right Spanish or French passage. Every query is forced through a tenant/ACL chokepoint that refuses to run unscoped, and mirrored Drive permissions mean a user only ever sees what they can actually open. Drive edits, deletions, and permission changes propagate back into the index through a changes.list cursor, so the index stays true over time. The whole thing ships as a multi-tenant monorepo with a validated Helm chart, non-root read-only containers, and KMS-backed key management.

Every file reaches a terminal state — a corrupt PDF lands in skipped and is never retried, a persistent transient failure dead-letters after N attempts, and killing a worker mid-crawl loses nothing because fetch, extract, and chunk are all idempotent. Cheap changes stay cheap: a rename, move, or re-share re-enters the pipeline at index and reuses the chunks and vectors already stored, so only a genuinely new revision pays for a re-download and a re-embed.

Why it's interesting: the retrieval config is measured, not assumed. A purpose-built evaluation corpus (12 subjects × 4 documents, vocabulary appearing nowhere else, hidden among ~2,000 decoys) with declared ground truth showed keyword search scoring 0.971 nDCG when the query shares words with the document and 0.033 when it doesn't — that gap is the entire case for carrying a vector index. The same harness moved RRF's k from the literature's 60 to 10 on evidence (ndcg@10 0.708 → 0.763), and a regression gate now fails the build if a chunking tweak or a dropped E5 prefix quietly makes search worse. Degradation is graceful too: if the reranker or the vector arm is down, results come back fused and flagged rather than as an error.

Reference-Guided Image Generation with LoRA

Stable Diffusion · LoRA fine-tuning · Image conditioning

A text-to-image tool that also takes one or more reference images, using LoRA adaptation so the output stays faithful to a subject, style, or object described in the prompt.

What it does

A reference-guided text-to-image tool built on Stable Diffusion: given one or more reference images of a subject, style, or object, it trains lightweight LoRA (Low-Rank Adaptation) weights on top of a frozen base diffusion model instead of fine-tuning the whole network. Those adapters capture the visual identity of the reference — a specific person, product, or art style — and get layered back onto the base model at generation time. A new text prompt then drives the scene, pose, or context, while the LoRA adapter keeps the output faithful to the reference. The result is fast, low-cost personalization of a general-purpose diffusion model without the cost of training or storing a full model copy per subject.
